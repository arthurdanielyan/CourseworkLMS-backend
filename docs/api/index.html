Library Management System · API v1

LMS API Reference

What the backend accepts and returns today: account access (signup with an email code, login, token refresh) the book catalog (search with filters, book details, filter lists), Favourites and Reviews. Generated from the backend's code on every change to the endpoints. This page is read-only and cannot send requests.

Rules that apply to every endpoint

  • Every path starts with /api/v1, and every JSON field is snake_case: full_name, access_token.
  • Authenticated requests send Authorization: Bearer <access_token>. The /api/v1/auth/** endpoints need no token.
  • A signup only accepts @polytechnic.am emails. The server picks the role: teacher for emails on the teacher list, student for everyone else.
  • Passwords are 8–72 characters, with upper and lower case letters, at least 2 digits and at least 1 special character.
  • Lists are paged with ?page=0&size=20 (page counts from 0, size up to 100). The filter lists (categories, languages, owners) are short and come whole.
  • A filter that takes several values repeats the parameter: ?category_id=2&category_id=3. Values of one filter match if any of them matches; different filters must all match.
  • A book with no owner is a University Book: owner is null, and the search finds them with university=true.
  • Every book carries favourite for the logged-in user. PUT and DELETE /api/v1/favourites/{book_id} answer 204 even when nothing changes, so the heart button can send them without checking first.
  • Each user has at most one Review per book, at /api/v1/books/{book_id}/reviews/mine: PUT writes or replaces it, DELETE removes it. The Positive filter is stars=4&stars=5, the Critical one stars=1&stars=2.

401 means only one thing: the access token is missing, expired or invalid. Call POST /api/v1/auth/refresh with the refresh token, store the new pair, and retry. Wrong passwords, bad codes and bad refresh tokens answer 400, so a refresh loop can't happen. Logged in but not allowed is 403.

Error format

Every failure is a problem response (RFC 9457). Switch on code; detail is for people. Validation failures also list the rejected fields, named as the client sends them.

{
  "type": "about:blank",
  "title": "Bad Request",
  "status": 400,
  "detail": "The request is invalid.",
  "code": "validation_failed",
  "errors": [
    { "field": "full_name", "message": "size must be between 2 and 100" }
  ]
}
